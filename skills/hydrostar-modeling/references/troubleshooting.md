# 建模、原生执行与导出的排错经验

按报错特征定位到具体阶段，保存失败日志和输入，再在独立工作目录修复。复验以该阶段的实际输出和验收门禁为准。以下经验来自本项目的实际执行；版本和触发条件属于各条记录的适用范围。

## 船体面元翘曲与端部尺度过渡

平顺船体仅增加均匀或余弦站位，仍可能在艏艉收缩处出现翘曲和邻接尺度超限。先保持水线、龙骨和剖面弧向对应，按四边形法向夹角与纵向边长局部细分站位，并平衡相邻纵向区间；每轮细分预估真实湿面数并为水线面留余量。

本项目 station_bands 的 adaptive_stations 为可选策略。它在显式翘曲门限附近细分站位，最终仍执行原请求的角度、翘曲、边长比、邻接尺度、CAD 体积/浮心及拓扑检查。若预算用尽，调整基础分段和分区后重建。通过单项形状指标只能说明该项已满足；交付使用完整验收结果。

已完成的课程船体例在 2029 个湿面、844 个水线面、全体 2873 个面元内通过验收；四边形 2018 个，端部三角形 11 个。该配置是一个实例，其他船型按其曲率和质量门限确定分段。

## 许可、MPI 与资源

原生求解和后处理按许可串行调度。曾出现并行启动多个原生算例导致许可错误，以及密网格在本机 4 进程下出现 libfabric/MPI 资源错误。先确认前一任务及其子进程已结束，再检查许可上下文和内存需求；按算例规模降低 MPI 进程数并复验。本机中等网格的 2 进程计算已成功，进程数仍应按实际机器和任务选择。

受限运行上下文中的许可失败与输入错误分别诊断。授权正常用户环境下执行后，以同一输入哈希、原生日志和全部质量门禁确认恢复；保留原失败日志。修改网格或物理参数后重新建立结果来源。

## 返回码为 0 的日志错误

HydroStar 8.2.0 的 HSprv 曾在输出 `ERROR: Error when opening file tmp/hsprv.log.log` 时返回 0。执行器同时检查进程返回码和日志中的原生错误标记，并验证预期文件实际生成且完整。遇到这一报错，先在当前算例工作目录建立可写 tmp/，再执行相同输入；成功条件包括无原生错误和完整 PVD 数据集。

## HSprv 数据依赖与自由面采样

HSprv 使用已完成计算的项目数据库。复制算例用于后处理时，同时保留实际需要的 bin/、hdf/、项目输入和参数；在副本中运行，原算例保持可追溯。网格、数据库、运动响应和场量须来自同一次计算。

8.2.0 在多水线闭环平台使用 CUT 路径时，曾先报告找不到轮廓首节点，随后在自由面处理处出现 Fortran EOF。该平台改用手册支持的 XMIN/XMAX/XSTP、YMIN/YMAX/YSTP 显式矩形采样，并沿用 AIRY、DIFWAVE、SHIP 和时间参数，实际导出了完整周期的船体压力、运动与波面。保存失败的 CUT 设置和日志，另存成功设置；这条经验限于已确认的版本与构型。

矩形采样会覆盖结构水线内部。显示前依据实际水线边界处理内部点或单元，并检查近体有效区域、自由面闭合关系、时间与单位。输出文件齐全是数据导出的验收；字段解释和图像验收继续分别完成。

## 命令式科研图导出

向外部命令传递中文图注或数学符号时，文本管道显式指定 UTF-8。本项目的页面语法检查在本机 UTF-8 环境通过，但 Windows CI 的默认 cp1252 在编码中文脚本时失败；为 subprocess 文本管道明确设置 UTF-8 后再复验。终端显示编码、控制文本编码与原生文件的字节归档分别处理。

HydroStar 的 Gnuplot 绘图路径可直接读取原生 .rao，以批处理脚本设置 SVG、pngcairo 或 pdfcairo 终端并保存。保留原始数值列、频率和浪向对应关系，幅值与相位分别核对。相位折回后采用点图或明确断线，避免跨越 ±180° 产生虚假的连接。实际打开导出图，检查字体、图例、坐标及单位后标为已验证。

ParaView 按手册的 HSprv 数据链路进行命令式导出，GIF 可以由其导出帧编码。查看器启动、原生字段数值检查、图片导出和视觉验收分别记录状态。运行时安装完成仍需执行最小读取与导出探针，成功后再批量生成。

ParaView 6.2.0 的多视口高清截图默认按放大比例缩放文字。本项目的四构型总览曾出现标题和尺寸说明放大后越过视口边界；在 `SaveScreenshot` 显式设置 `FontScaling="Do not scale fonts"` 后，按最终图片像素控制字号，并为结构、标题和尺寸说明分别预留空间。逐视图检查标题完整、前后景无裁切、图例无重叠。批量离屏命令可加 `--disable-registry`；本机受限环境曾在图片已成功导出后报告用户设置文件不可写，禁用用户设置读写后，同一导出正常完成。该设置不代替数据与图片验收。

## HSprv 场量与完整复响应的独立核对

8.2.0 旧格式 wave.pvd 的 VTS 点坐标 z 已经包含波面高程，直接再次 Warp 会重复叠加。其 Displacement 为九分量，官方宏取第 8 分量（从 0 计数）显示总波面；第 7 分量为入射，第 6 分量为绕射，前六项为运动相关辐射。实际文件仍须通过解析入射场、分量闭合及独立原生分解核对后确认解释。

本项目的独立核对发现：原生入射与绕射分量可以匹配 HSPRS，但旧格式 HSprv 总场的运动相关部分与完整复响应有偏差。仅验证九分量相加与总场一致，以及船体运动正确，并不足以验收总波面。已检查的 0.5 m 波幅平台工况中，整个外部采样区的最大复总高程差约为 0.0685 m；集装箱船约为 0.2681 m。这些数值属于本次工况，其他版本和算例须独立复核。

处理方法是保留原始 HSprv 导出和差异报告，通过 HSPRS 的 WAVEDECOMPOSITION 重新提取同一场点的原生 PRESSURE、WAVEDEC INC、WAVEDEC DIF，以及选定点的六个单位速度辐射系数。以完整复运动计算 `i*omega*U_j*RAD_j`，转动先换算为弧度，并明确辐射参考点。其和应与原生总场减去入射、绕射相符。验收后的复总场、入射、绕射用于 ParaView；散射和辐射在复数域分别相减后按同一物理相位重建。旧格式 HSprv 总场作为诊断保留，展示字段明确指向验收后的原生复场量。

压力优先使用经独立核对的 HSPRS 面元采样：COEFHDS=1 的随体一阶扰动与 COEFHDS=0 的欧拉扰动分别提取，验证两者的静水运动修正，检查有限水深入射解及沿外法向偏移的敏感性。压力头按 rho*g*A/1000 转为 kPa，其中 A 只对单位波幅 RAO 使用一次；HSprv 已按 AIRY 波幅重建的时域值不再重复乘 A。平均静水压力另存，曲面压力按实际 HST 面元着色。

## 单频动画配套计算

本机 HSprv 在含 231 个频率的数据库上，即使 AIRY 指定单频，也遍历全频率完成场量计算，曾触及 1200 s 后处理时限。先保留完整扫频，再为动画建立相同 HST、质量、重心、惯性、恢复、阻尼和环境的单频配套计算。配套例本身通过全部原生门禁，并与原扫频相应工况的六自由度复响应逐项比较后使用。该步骤缩小后处理数据范围，同时保留完整频率研究；记录两套输入、网格哈希、选定频率与浪向、复响应差和各自执行状态。

## Windows ParaView 的 DLL 构建兼容

本机 conda-forge ParaView 6.2.0 / Python 3.12 安装曾出现 `0xC0000135`（缺少 DLL）和 `0xC0000139`（导入入口不匹配）。先检查可执行文件及递归依赖，区分缺失库与 ABI 不匹配。此例先定位到 `vtkcgns-9.7.dll`，随后定位到 Protobuf 与 Abseil 的导入符号；单纯补 PATH 无法解决这些构建差异。

已验证组合为 paraview=6.2.0=py312hd8a066f_1、vtk-base=9.7.0=py312h2124641_1、libprotobuf=7.35.1=h1a71995_3 和 libabseil=20260526.0。它是该 Windows 运行环境的复现记录，其他平台或版本使用自身兼容组合。运行前将所选环境及其 Library/bin 放在进程 PATH 前部，避免混用其他安装的 DLL。

修复后已通过 `pvpython --force-offscreen-rendering` 读取 HSprv 的 wave.pvd，并以 ParaView SaveScreenshot 实际导出 PNG。保留环境版本清单、最小读取/导出日志和图片，再进入批量任务。PE 检查大体积 VTK 库时，注意分析工具可能默认截断导出符号表；应核对其警告和符号上限，避免把分析器截断误判为真实缺失。

## 新经验的记录方式

ParaView 的 TrivialProducer 直接替换客户端输出后，需要同时使服务器管理代理失效并更新管线。本项目曾出现 PNG 文件字节及时间文字变化、各场量视口像素却保持不变的情况；使用客户端 Modified、代理 `SMProxy.MarkModified(SMProxy)` 和 UpdatePipeline 后，五种场量均随相位更新。复验逐视图的 RGB 像素变化，并在最终 GIF 中排除标题和时间文字区域再次检查；PNG 文件哈希不同本身不能证明动图场量正在变化。

原生 RAO 归档保留实际字节和换行。本项目曾因 `read_text()` 的自动换行转换，使 Windows 原生输出的归档正文与原文件哈希不同；改为 `read_bytes().decode(...)` 保存原始正文，并对压缩归档中的每条记录重新计算哈希。参数解析可以规范化文本，正式原生输出的保存与来源核验按原字节执行。

带哈希的原生数据目录在 Git 中保留原字节；绘图脚本按仓库规定的 LF 换行保存后再生成脚本哈希。发布前从全新检出核对原生数据、脚本和媒体记录，避免工作区换行与 Git 归一化导致来源不一致。

每项新增经验写明软件版本、触发输入、关键日志、确认原因、修复动作和复验输出。尚未确认的推测留在任务排查记录，确认后再纳入本文件。通用修复进入执行器或生成器，并用能复现原问题的检查覆盖；单一算例的绕行方法保持具体适用范围。
